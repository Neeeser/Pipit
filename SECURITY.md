# Security policy

## Supported version

Security fixes go into the latest release. Update to the newest disk image on
the [releases page](https://github.com/Neeeser/Pipit/releases/latest) before
reporting a problem.

## Reporting a vulnerability

Report privately through GitHub. Open the repository's Security tab and choose
"Report a vulnerability". That form is private to the maintainers. Do not open
a public issue for a security problem, and do not post one in a pull request.

Include the macOS version, the Pipit version, and the steps that reproduce the
problem. Leave out recordings, transcripts, and the names of people on a real
call. Describe the case with synthetic data instead.

You get an acknowledgement within a week. The report stays private until a fix
ships, and the advisory credits you unless you ask otherwise.
